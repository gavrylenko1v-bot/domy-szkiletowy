# VERTEX I.S.O — доработки и проверка 25.10.2026

## Результат и границы

Подготовлена среда Node.js 24.19.0 / npm 11 и доработана существующая реализация Next.js. Это продолжение уже имевшегося сайта, а не создание всего сайта с нуля. Каталог, страницы компании, формы, серверная валидация, SEO и исходный логотип существовали до этой работы.

Сайт пригоден для локальной разработки и проверки. Публичный коммерческий запуск требует данных владельца, почтовой интеграции, юридического завершения документов и архитектурного согласования. Статус публикации не включён, индексация по умолчанию закрыта.

## Найдено и исправлено

- Галерея не имела полноэкранного режима: добавлен нативный модальный dialog, стрелки, Home/End, Escape, возврат фокуса и блокировка прокрутки фона.
- На карточках не было санузлов, крыши и явной текстовой ссылки: добавлены характеристики и «Zobacz projekt».
- В интерфейсе были подписи 7–11 px: размеры текста CSS подняты как минимум до 14 px. Поля выбора на телефоне — 16 px. Заголовки используют Manrope, остальной интерфейс Inter; шрифты и лицензии хранятся локально, включая польские символы.
- После увеличения шрифтов перестроен мобильный hero: текст и кнопки идут в потоке и могут увеличивать блок. На промежуточных ширинах CTA отделены от описания дома.
- Цвета приведены к графиту, тёплому белому и древесному акценту. Для текста на тонированных поверхностях используется более тёмный вариант дополнительного серого. Контраст проблемных номеров и подписей исправлен по результатам axe.
- Для каждого проекта добавлены предварительный баланс помещений, оценка общей площади, комнаты, угол крыши как концептуальное допущение, конструкция, остекление, терраса, варианты отделки, комплектации и изменений.
- В SVG добавлены размеры зон. Таблица помещений отдельно обозначена как предварительный бюджет полезной площади: её нельзя выдавать за обмер SVG.
- Добавлена квадратная социальная иконка SVG. Основной существующий логотип сохранён, цвета всех его вариантов согласованы.
- Дополнены паспорта: перечень медиа, программа помещений, ограничения и отдельные промпты для новых ракурсов.

## Изображения и планировки

Существовавшие 20 рендеров дополнены 70 новыми оригинальными AI-визуализациями. В каждой галерее: основной вид, второй вид, сад, терраса, боковой фасад, сверху, гостиная, кухня, спальня и SVG-схема. Всего **90 WebP-рендеров и 10 схем**, 100 материалов в галереях. Новые WebP ограничены шириной 1440 px, quality 82; оригиналы генерации сохранены вне checkout в `/workspace/generated_images`.

Изображения создавались с экстерьером соответствующего дома в качестве референса. Проверены обзорные листы всех новых ракурсов. В спальне STODOŁA 60 замечено и исправлено чрезмерно большое треугольное окно.

**Архитектурная координация не завершена.** Эти изображения не получены из одной CAD/BIM-модели. Визуальная проверка не доказывает точное совпадение всех проёмов, размеров и помещений между ракурсами. SVG остаются схемами зон: двери, проходы, лестницы, перегородки, высоты под скосами и оконные ведомости требуют разработки и согласования архитектором. Таблицы помещений — согласованный арифметически предварительный бюджет, а не подтверждённая измерениями планировка. Каталог нельзя продавать как готовую строительную документацию.

Все концепции сохраняют двускатную крышу существующей линейки. Полная замена линейки на десять новых архитектурно согласованных проектов с разными типами крыш в этой доработке не выполнена.

## Проверки

Команды: `npm ci --cache /workspace/.npm-cache`, `npm run build`, `npm run lint`, `npm run typecheck`, `npm test`, `CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e`.

Проверяются 18 публичных маршрутов, все десять проектов, локальные изображения, внутренние ссылки и якоря, уникальные SEO-метаданные, фильтры, сортировка, меню, галереи, FAQ, 404 и отказ формы при ненастроенной доставке. Дополнительная проверка ширин: 320, 375, 390, 430, 768, 1024, 1440 и 1920 px; снимки каталога сохраняются в `test-results/`. Мобильный профиль эмулирует iPhone в Chromium, а не настоящий Safari/iPhone.

Положительный ответ Resend проверяется только моком. Реальная отправка не выполнялась. Полевые Core Web Vitals и показатели публичного домена не измерены. Проверка публичного сайта по указанному URL блокируется прокси среды (CONNECT 403); этот ответ не доказывает неисправность сайта.

Итоговые результаты текущего запуска фиксируются в конце этого отчёта после завершения проверок.

## Настройки среды и действия владельца

Сохранены `install_script` и `start_skill` с рабочим каталогом, установкой через lockfile, запуском, проверками готовности и указанием не создавать worktree. Сохранено требование `RESEND_API_KEY` с назначением `api.resend.com`, имена переменных отправителя, получателя и публичного origin. В разрешённые пользовательские домены черновика добавлены `domy-szkiletowy.vercel.app` и `api.resend.com`. Значения секретов не сохранялись в коде или чате. Изменения черновика не означают применение к текущей машине или публикацию среды.

Для завершения:

1. Владелец предоставляет реальные юридические данные, NIP, адрес, контакты, территорию работы и утверждённый состав услуг.
2. Архитектор согласует точные планы, площади, окна, двери, лестницы, конструкции и изображения; при требовании полезной площади до 70 м² нужна переработка трёх больших концепций.
3. Настраиваются Resend и подтверждённый домен отправителя; адреса отправителя/получателя вводятся в настройках. Для production нужны endpoint и token Upstash Redis. Домен Redis пока неизвестен, поэтому он не выдуман и секрет с произвольным назначением не объявлен.
4. Проверяется настоящая доставка тестового письма на согласованный адрес, затем завершаются RODO-документы и условия хранения данных.
5. Подключается Vercel/хостинг, задаётся публичный origin, проверяется HTTPS. Только после проверки включается `SITE_PUBLISHED=true` и выполняется новая сборка.
6. Для публикации облачной среды нужно проверить и сохранить её настройки, затем опубликовать среду в интерфейсе продукта. Новая задача после восстановления snapshot здесь не проверялась.
